# 厂商原生接入：OSS、OBS、COS、TOS

StorageLab 提供阿里云 OSS、华为云 OBS、腾讯云 COS、火山引擎 TOS 四家原生接入。主进程使用锁定的官方 `ali-oss@6.23.0`、`esdk-obs-nodejs@3.26.2`、`cos-nodejs-sdk-v5@3.0.0`、`@volcengine/tos-sdk@2.9.1`，请求和下载链接由对应 SDK 签名。其他提供商的 SDK 选择及七牛评估见 [云接入说明](cloud-providers.md)。

## 配置与旧连接

| 提供商   | Endpoint 示例                              | 区域           | 凭证                                                          |
| -------- | ------------------------------------------ | -------------- | ------------------------------------------------------------- |
| OSS 原生 | `https://oss-cn-shanghai.aliyuncs.com`     | `cn-shanghai`  | AccessKey ID / AccessKey Secret；临时凭证另填 SecurityToken   |
| OBS 原生 | `https://obs.cn-north-4.myhuaweicloud.com` | `cn-north-4`   | AK / SK；临时凭证另填 SecurityToken                           |
| COS 原生 | `https://cos.ap-guangzhou.myqcloud.com`    | `ap-guangzhou` | SecretId / SecretKey；临时 Token 填 Session Token             |
| TOS 原生 | `https://tos-cn-beijing.volces.com`        | `cn-beijing`   | AccessKey ID / Secret Access Key；临时 Token 填 Session Token |

桶名单独填写；Endpoint 不应包含桶名、对象路径、查询或签名参数。OBS 原生使用虚拟主机寻址，不接受 IP 或 Path style，以防 SDK 切换为兼容签名。OSS 原生不能使用 `s3.oss-…` 专用地址。COS 原生也禁用 Path style，桶名称需含 `-APPID`；标准地址不要带桶前缀。TOS 原生使用 `tos-…`，拒绝 `tos-s3-…`。自定义 Endpoint 视为服务基础地址，不自动猜测桶绑定 CNAME。

新建连接只展示各厂商原生入口，移除阿里云/COS/TOS 三个旧版 S3 选项。原有 `aliyun`、`cos`、`tos` 连接保留兼容读取；编辑时只为当前已保存连接保留其旧版身份，迁移保存后不再展示。COS/TOS 提供显式“迁移为原生”按钮：COS 保留标准服务域名，TOS 将标准 `tos-s3-地域.volces.com` 转为 `tos-地域.volces.com`；自定义地址保留供核对。旧阿里云可明确迁移为 OSS 原生：标准 `s3.oss-地域.aliyuncs.com` 地址可转换为 `oss-地域.aliyuncs.com`，自定义地址保留并要求核对。迁移只修改当前表单，保存后生效，取消不会修改已存连接。

迁移不变更 SQLite 结构、应用 ID、凭证加密方式或已有任务记录。旧协议的 UploadId 与续传记录不能直接换成原生协议使用；配置指纹不一致时，现有续传保护会阻止恢复。建议处理完旧上传后再保存迁移。

## 功能与保护

四家原生接入复用同一工作台，支持桶和对象浏览、分页、属性、预览、流式下载、普通及分片上传、断点续传、分享、删除、标签、历史版本和受控复制/元数据编辑。实际操作仍受账号权限、桶设置及厂商限制影响；配置预设不代表权限检查通过。

原生上传要求明确允许覆盖，避免把未经云端验证的条件写当作可靠保护。未知字段或不支持的条件会拒绝执行，不能静默移除。重命名沿用保守策略：复制后保留源对象，并显示原因。恢复历史版本继续要求版本控制开启、不可变源版本、ETag 与大小核验。

OBS 官方 SDK 的 XML 序列化存在转义限制；适配层对 XML 请求字段中的 `<`、`>`、回车及无效 Unicode 字符提前拒绝，防止批量删除目标被改变。普通 Key 中的 `&`、引号、换行、制表符与有效 Unicode 已通过实际 XML 往返验证。OSS 的 XML 请求则对回车使用数值实体并拒绝无效 XML 字符。

包含独立 `.` 或 `..` 路径段的 Key 可按原始值请求，但拒绝生成签名下载链接，避免浏览器折叠路径。OBS 对无明确版本且 Key 含字面量 `?versionId=` 的复制请求明确拒绝，避免 SDK 将 Key 误解为版本参数；可先下载核实，或使用实际不可变版本。

SDK 自动重试关闭。创建/完成分片或复制返回网络错误时，服务端可能已经写入；应刷新核实，不要盲目重试。取消和关闭会终止真实请求；下载响应保持流式处理。OSS 使用原生 V4 签名，OBS 固定原生 OBS 签名并关闭协商回退；TLS 证书及主机名校验保持开启。

四家原生下载等待响应头有界，收到响应后按 socket 无数据的持续时间计算超时；正常大文件持续传输不受总耗时阈值截断。监控不读取正文，不改变背压；取消、关闭、超时仍销毁实际请求并清理临时文件。非 GET 操作保留原请求时限。

列桶在公共操作层受控聚合，最多100页/10000桶。OSS/COS 使用 marker，OBS 将 ContinuationToken 映射为 Marker、BucketName 映射为 Name；TOS官方接口单次返回全量，不强加分页参数。游标异常或中途失败明确报错，仍可打开已知桶。

## 维护边界

`electron/providers/client.js` 负责选择适配器，`oss.js`、`obs.js`、`cos.js`、`tos.js` 负责厂商参数、响应、错误和请求生命周期。为兼容现有任务协调器，内部暂时保留 AWS Command/响应形状；四家原生网络请求不由 AWS SDK 发送。后续迁移其他提供商时继续沿用此边界，避免复制界面与传输队列。

验证结果与限制在本次交接中记录。真实官方 SDK 的本地协议测试与 Electron 回环测试只证明相应客户端行为；真实云账号、真实云策略、安装包和其他操作系统需分别验收。测试不访问用户云桶或146。

## COS / TOS 的实现边界

COS SDK 3.0.0 的高层网络实现硬编码结果不明请求重试，无法通过 `ChunkRetryTimes` 关闭。因此适配器调用官方 SDK 的原生签名和 XML 解析，再以受控 Node HTTP/HTTPS 发送一次请求；没有自写 COS 签名算法，也没有使用 S3 网络请求。官方签名、实际 Host/原始路径、Token 和条件头已在回环线上核验。高层 SDK 的自动重试不进入本工具请求链。

TOS 使用官方 SDK 的原生 `fetch` 和 TOS4 签名，通过每次请求的 `axiosOpts.adapter` 注入受控 HTTP adapter，保留原始 Key、流式下载、取消及超时。SDK 构造器会重设 `requestAdapter`，不能仅在构造时注入。SDK 2.9.1 的签名查询区域读取问题通过局部调用上下文兼容，不改全局 SDK 或签名算法；依赖升级时应保留传输生效和签名区域两项回归。

COS XML 请求正确转义并对回车使用字符实体，无效 XML 字符提前拒绝。TOS 原生 JSON 不进行 XML 预转义。两者都拒绝未知字段或不支持的条件；分片后续请求只接受与初始化一致的继承字段。原始点路径可直接请求，浏览器签名链接仍拒绝独立 `.` / `..` 段。

异常 XML/JSON、错误响应根结构及缺少必要 ETag/UploadId 的写响应会拒绝，避免将无效响应报为完成。COS 复制指令由内部 COPY/REPLACE 转为原生 Copy/Replaced。TOS 非流式响应限制 16 MiB。

两家均已实现标签、版本、分片、复制和预签名接口映射，但本地协议服务不证明真实云端所有权限、策略或边界行为。默认不覆盖上传、条件删除和受控重命名继续遵循前述保守保护。
