# 目录交付持续验收（2026-11-01）

本轮针对新增目录交付模块，使用真实 Electron 生产主入口、固定 IPC 白名单、AWS S3 SDK、本地 HTTP S3 兼容夹具和真实磁盘。数据目录为独立临时目录，不访问146或真实云账号。

## 复现与维护入口

`npm run test:directory:soak -- --seconds=1200 --idle=180` 先构建生产 renderer，再启动可见原生窗口。可用 `--output=<目录>` 选择报告位置；`--seconds=8 --idle=1` 仅用于检查夹具流程，不能代替正式长跑。

脚本位于 `scripts/directory-soak.mjs`；原生测试宿主 `tests/native/directory-soak-host.mjs` 只隔离 appData 和返回生成的系统 picker 测试路径，生产 IPC 不增加文件系统入口。它不是实际云服务，也没有测试系统文件选择面板的人工交互。

四个样本包含空文件、中文及空格路径、嵌套目录和二进制文件。首次上传及导出由真实 DOM 控件触发；持续阶段通过生产 renderer bridge 反复发起目录批次，独立比对远端字节与下载磁盘 SHA-256。更新后的维护脚本还定期通过 DOM 切换最新批次，避免只停留在最初的结果页。

故障注入包括上传远端回读损坏、提交后核验取消、预览后远端变化、HTTP503及恢复、下载跳过。取消保留已经提交的传输证据；损坏或过期预览不得标为核验成功。负载后保持同一进程静置，完成后单独测试退出重启、SQLite quick_check及历史上限。

## 本轮修复

1. **中断批次的文件条目仍显示运行中。** 退出保存批次中断状态时，异步取消可能尚未完成；旧启动逻辑只修正 running/cancelling 批次。现在退出同步归一未完成条目，启动也修复已有 interrupted 批次中的 ready/queued/running 条目。完成文件、核验摘要和实际提交状态保留，已经稳定的历史中断时间不在每次启动时改写。
2. **历史批次淘汰后反复提示不存在。** 当前所选结果超过20条终态保留范围后，窗口继续轮询旧ID，且列表不能更新。现在根据最新列表清除已淘汰选择并说明原因；选择其他批次时清除旧提示。

两个问题均有先失败再通过的回归。目录服务回归覆盖终态保存失败后的会话结果、提交后取消、200条普通任务之外的完整批次、schema2迁移和重启归一。
